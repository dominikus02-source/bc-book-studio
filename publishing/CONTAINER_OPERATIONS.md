# Isolated Quarto renderer (staging design)

This is an opt-in standalone renderer. It **must never** be invoked directly on the production host outside an enforced container runtime. The builder and CI test image installs Quarto 1.11.9 (verified installation SHA-256), Python 3, EPUBCheck, Poppler `pdfinfo`, and Noto/DejaVu fonts. No arbitrary user plugins/extensions, Jupyter, R, Julia, or Node execution are enabled.

## Build

```bash
docker build -f publishing/Dockerfile -t bc-book-studio-qmd:1.11.9 .
```

## Run (on a dedicated, unprivileged staging worker)

```bash
mkdir -p /var/lib/bc-qmd/jobs/example/output
# First put ONLY sources validated and generated by qmd_pipeline into jobs/example/input
bash publishing/run-sandbox.sh /var/lib/bc-qmd/jobs/example/input /var/lib/bc-qmd/jobs/example/output
```

Job inputs MUST contain generator-created `manifest.json` and exact verified file hashes. The renderer refuses preview, missing approval, extra files, symlinks, and tampered inputs; it cannot independently attest that an approval was issued by a real human, which **must** be enforced by trusted backend authentication and immutable snapshot storage.

The shell launcher uses `--network none`, read-only root FS, no capabilities, no new privileges, process/CPU/memory limits and limited tmpfs. Output directory permissions must permit the unprivileged UID/GID 65532 to write. Use a dedicated non-root Docker host / rootless daemon with seccomp/AppArmor and disk quotas; `--network none` alone is not a complete security boundary. Worker timeout and job cancellation should be enforced outside the container, with a durable queue and audited outputs. Do not attach credentials, Docker socket, host filesystem, production DB or `.env`.

## Outputs

Each format goes to its own subdirectory, including the HTML site. `manifest.json` records input snapshot, approval ID, source chapter hashes, Quarto version, render commands and warning counts, and SHA-256/size of each produced file. EPUBCheck and `pdfinfo` are executed; these **do not certify EPUB accessibility or PDF/UA**. Install and test veraPDF and tagged PDF settings before any accessibility claims, and require QA plus human release approval.

## Remaining production blockers

- Durable queue + retries/DLQ, cross-service authentication/RBAC, immutable approval proof and atomically persisted job/manifest status.
- CI Docker build and runtime policy/security validation (staging, network isolation, seccomp, resource exhaustion, disk limits).
- True bibliographic integrity checks against reviewed references, source citation support, glossary/index/advanced chemistry typography, verified asset licensing and editorial subject expert review.
- Tagged PDF / veraPDF, end-to-end publishing approval flow, signed/atomic artifact storage and restored jobs after worker kill.
- Sizing and load tests (especially limited VPS 4 vCPU/8GB); production flags remain off.
